## Description
ADOPT: common-actions rule — deterministic anti-mush gate for shot/action text (script-pass doctrine). Implements the "common actions only" principle from shuohao-skills script-pass (docs/extraction/shuohao-skills/pass-methodology-outline.md section 4 + RUBRIC-methodology-extraction.md A4.2; GLM verdict ADOPT): video models only act what they have seen millions of times — boarding, sitting, handing, nodding are safe; precise physics interaction, micro-expression direction, and inch-scale motion will break. The judgment test is verbatim: "is this action common in real-life video?" This story turns that writing discipline into a machine-checkable gate on our shot/action text (same pattern as no-names gate WD-4jpr and beat-claims WD-4s1b: descriptions for humans, claims for machines to check). Components: 1. Common-action lexicon + risk-pattern registry (new module gates/common_actions.py): documented data file (datasets/common-actions.json or equivalent) with two sections — (a) SAFE: seed list of common action verbs/phrases the model has seen millions of times (walking, sitting, standing, turning, handing over, nodding, opening a door, drinking, typing, etc.); (b) RISKY: patterns that historically produce mush in WanGP H3 — precise physics interaction (pole blocks crate, domino chain, ball ricochet), micro-expression direction (flicker of doubt, slight twitch, barely-there smile), inch-scale displacement (moves one inch closer, tilts by a degree, subtle shift). Each risky entry carries: id, surface pattern (regex or phrase), category (physics | micro_expression | fine_displacement), rationale string citing the doctrine. 2. Deterministic checker check_common_actions(text) -> list[ActionViolation]: flags every RISKY pattern hit with id/category/span; NO LLM, NO network. SAFE-list presence is NOT required (a shot can use any common action not in the seed list — the gate only rejects known-bad patterns, mirroring the no-names gate exact-match-only philosophy: a mis-blocking gate is worse than no gate). Typed violation dataclass, distinct categories. 3. Wiring: gate wired into PromptDirector brief validation alongside _reject_meta_hints / _reject_registry_names (predict/prompt_director.py) — briefs whose subject/motion text trips a RISKY pattern raise the typed failure through the existing rejection path. Plus standalone CLI scripts/check_common_actions.py (pattern: scripts/check_names.py) taking inline text or a file, printing per-hit report, exit 0 clean / 1 violations / 2 usage error. 4. Doc: docs/common-actions.md citing pass-methodology-outline.md (section 4, script-pass L10-18 table) and RUBRIC A4.2 with file:line refs; documents the measure-then-threshold stance (seed list starts small, grows from observed 3090 mush cases — each addition must cite the failing render).

## Acceptance Criteria
- [ ] a) TDD suite for the checker: each seeded RISKY category fires on a positive sample; word-boundary/case behavior pinned; false-positive cases covered (safe common words containing risky substrings do NOT fire); empty/whitespace input handled distinctly (typed, loud skip when optional inputs absent — never silent); all deterministic, zero-model. b) Briefs tripping a RISKY pattern are rejected with a typed failure using the same pattern as the meta-hint guard (ValueError during RenderBrief validation, caught by PromptDirector.forward's existing rejection path). c) CLI works on arbitrary text (stdin/args) and files; non-zero exit + clear per-hit report on violations, zero exit when clean, distinct usage-error exit. d) Doc checked in under docs/ citing the extraction docs (file:line refs); registry schema documented + seed data checked in. e) Full test suite green + implementation captured (PR trail, evidence).
