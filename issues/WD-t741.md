## Description

## USER INTENT
The operator directed: “it needs to be able to generate everything that Maestro can”. Wangp remains the governed engine underneath the product surface. This epic closes capability gaps with typed plans, durable queues, authorized host execution, real gates, and honest status; it never converts vendor documentation, settings, or a plan into a generation claim.

## Context (Embedded)
- Reference surface is Maestro v2.3.0 as verified from its README/docs today. Reference popularity/release metadata is context, not capability evidence.
- Current Wangp main `be1494f` has an accepted governed H3/Wan2GP film pipeline and stable no-GPU `wgp` planning/readiness surface. Broad Maestro image, music, speech breadth, SFX/post, finishing, portable characters, director surface, first-run platform, and editor capabilities require the children below.
- Existing product-front-door work already in flight is WD-u8yk (one-command install and v0.1.0 release note) and WD-cpb8 (`wgp content` plus first-run capability report). They are related, not children of this epic, and must not be duplicated here.

## OUT OF SCOPE
- Relaxing, hiding, or bypassing Whisper, identity-vision, mouth-box, SyncNet, assembly, provenance, or queue gates.
- GPU execution, model download, host mutation, external paid APIs, network research, tagging, publishing, commit, or push authorized merely by creating this backlog.
- Rewriting accepted historical render evidence or treating third-party model output as repository-owned content.

## Required Outcomes
### no-GPU verifiable now
- Each child proves typed request normalization, deterministic planning, durable queue shape, typed preflight failures, dry-run reconstruction, redacted diagnostics, and documentation without GPU/SSH/network unless a child explicitly authorizes a local read-only process.
- The capability matrix is honest: rows remain `no_gpu_verified`, `blocked`, or `not_started` until recorded generation evidence exists.
- Dependency order is machine-checked and no child weakens accepted gates or claims parity from a prompt.

### requires an authorized host render
- Actual generated artifacts and gate evidence are produced only after separate operator authorization per run. Each child names its required artifact classes and run-bundle fields.
- No story may claim generation it has not run; unsupported hardware/backend state is recorded as blocked/unavailable, never as success.

## Testing Requirements
- Every child requires real-process tests with real CLI/files/queues/subprocesses and no mocks. GPU-dependent assertions live only in recorded run-bundle review, not fabricated test fixtures.
- Scoped child tests plus the existing full suite must pass at each delivery. Exact commands are listed in each child.
- At closeout, `pvg lint --backlog --epic WD-t741` and the dependency cycle check must pass, and every matrix row must cite accepted evidence.

- Epic Gate part (a): every capability child is accepted with real no-mock evidence and, where the contract requires generation, a separately authorized run bundle.
