## Acceptance Criteria

1. `docs/CHANGELOG.md` exists with a header stating the decision-record purpose (vs release-log) and the entry anatomy (failure → root cause → chosen fix → rejected alternatives + why → measured evidence).
2. Seven entries (#27–#33), each with all five anatomy fields populated; thresholds/behaviors carry measured values with the command that produced them.
3. Evidence is MEASURED: every numeric claim (test counts, gate fire counts, rejection rates) is reproducible by re-running the cited command at the cited commit; no invented numbers.
4. Docs-tier lane: PR-only, no code changes, no test changes; full suite still green at the branch head (unchanged from main).
5. Each entry names at least one rejected alternative with a reason (the format's core value — decisions are visible, not just outcomes).

## Design

- Append-only going forward: future ADOPT merges add entries in the same format (this story establishes the convention; the master sequence comment on WD-j9nx records that).
- No auto-generation from git log — entries are authored with judgment (what was rejected, why), which is exactly what a script cannot produce.
- Keep entries compact (~40-60 lines each); the corpus is a reference, not a narrative.
